# KD PAY LLC - DATA MODEL AND SQL CONVENTIONS

This document is the single source of truth for table ownership and structure.
A step creates only the tables assigned to it. Later steps extend a table through a new
migration that adds columns, never by editing the original migration.

---

## 1. Universal column contract

Every table, without exception:

| Column | Type | Rule |
| --- | --- | --- |
| id | uuid primary key | UUID v7 generated by uuid_generate_v7() |
| company_id | uuid | FK companies(id) ON DELETE RESTRICT, null only for platform scope |
| created_at | timestamptz | default now(), UTC |
| updated_at | timestamptz | maintained by set_updated_at() trigger |
| deleted_at | timestamptz null | soft delete only, hard delete revoked |
| version | integer not null default 0 | required on every editable table (charter R15) |

Additional required columns by concern:

- Money: numeric(18,4) not null default 0.0000, currency char(3) fixed 'USD'
- Timestamps: timestamptz only, never timestamp without time zone
- Actor fields: created_by uuid null, updated_by uuid null
- External identifiers: text with a partial unique index scoped to company_id
- Searchable encrypted fields: a sibling blind index column named {field}_bidx (bytea or text)

Platform scope tables carry a check constraint:
`CHECK (is_platform_scope OR company_id IS NOT NULL)` where is_platform_scope is a generated
column derived from a table level setting, implemented in Step 02.

## 2. Naming

- Tables: snake_case plural
- Columns: snake_case singular
- Enums: snake_case plus _enum suffix, created with duplicate_object guard
- Index: idx_{table}_{columns}
- Foreign key: fk_{table}_{target}
- Check: chk_{table}_{column}_{rule}
- Policy: pol_{table}_{scope}_{action}
- Trigger: trg_{table}_{purpose}
- Function: fn_{domain}_{action}

## 3. Required indexes

- Company scoped query: (company_id, created_at desc) on every tenant table
- Soft delete: partial index WHERE deleted_at IS NULL on every unique business key
- Foreign keys used for joins: always indexed
- Status filters: (company_id, status, created_at desc) where the table has status
- Search: trigram index only where a search UI exists, never as a default
- Hot payment lookups: unique (provider, provider_intent_id), unique (provider, provider_event_id)

## 4. RLS pattern

Every table:

1. `ALTER TABLE t ENABLE ROW LEVEL SECURITY;`
2. `ALTER TABLE t FORCE ROW LEVEL SECURITY;`
3. No policy for anon except explicitly public read tables (countries, plans catalogue)
4. Owner scope policy: `USING (company_id = fn_current_company_id() AND deleted_at IS NULL)`
5. Platform scope policy: `USING (fn_is_platform_staff() AND fn_has_permission('<resource>.read'))`
6. Write policies require the matching permission key, not only the role
7. Service role bypass exists only in the server admin client, never imported by a client file
8. Cross tenant access returns 404 at the API layer, even when RLS filtered the row

Helper functions are STABLE SECURITY DEFINER with a locked search_path, and read identity from
the JWT claims cache so a page render does not re evaluate per row.

## 5. Audit pattern

- `audit_logs` is append only. Update and delete privileges are revoked.
- Trigger `fn_audit_row()` writes actor, action, before and after jsonb, correlation id.
- Mutations performed by the service role still write audit with actor from the request context
  and actor_role 'service'.
- Payment, refund, payout, KYC, processor credential and fee changes additionally write a
  domain event row, because those flows are read by the evidence pack builder.
- Hash chain: current_hash = sha256(previous_hash || canonical_json(row)). Verification tool is
  built in Step 15 and exercised in Step 16.

## 6. Idempotency pattern

- Client sends Idempotency-Key for every payment and every queued mutation
- Row in idempotency_keys keyed by (scope, key) with request_hash
- Same key with a different request hash returns 409 with a typed error
- Same key with the same hash replays the stored response, including the stored status code
- Rows expire after 24 hours, cleaned by a cron job with a bounded batch

## 7. Job queue contract

- jobs.kind values are declared in `lib/jobs/kinds.ts` with a Zod payload schema per kind
- Step 02 creates the queue; Step 02 also declares the job kinds that earlier steps will need
  to enqueue, including email.send, pdf.render, export.csv, webhook.retry, payout.process,
  settlement.reconcile, screening.rescreen, billing.reminder, retention.purge
- A step enqueues rows for kinds it does not consume. The consumer is implemented in the owning
  step. A job kind never runs before its consumer exists, because cron dispatch for a kind is
  registered only in the owning step.
- Every job is idempotent by kind plus natural key plus correlation id

(pending, active, suspended, closed), is_platform, onboarding_state, owner_user_id,
platform_fee_percent numeric(7,4) null (override), settlement_hold_days int null,

### invoices

### payment_intents
id, company_id, invoice_id, client_id, provider_key, mode, amount, currency 'USD',

### payments
id, company_id, payment_intent_id, invoice_id, provider_key, provider_payment_id,
provider_charge_id, amount, fee_amount, platform_fee_amount, net_amount, currency,

### ledger_entries

id, company_id (platform), provider_key, active_mode, activated_at, activated_by,

## 11. Performance rules applied at the schema level

- No SELECT * in services. Column lists are explicit and match the UI need.
- Denormalized counters maintained by trigger, never by application read modify write:
  invoice.total, invoice.amount_paid, invoice.balance_due, owner_balances.available,
  owner_balances.pending, clients.open_balance_cached.
- Reporting aggregates come from functions named fn_report_{domain} returning one row, so the
  dashboard issues one query instead of five.
- No jsonb column is filtered without an expression index.
- Every list query is ordered by (created_at desc, id desc) and paginated by keyset.
- Large text columns (rendered HTML, PDF bytes) are never stored in the hot table; they live in
  file storage or a separate *_content table read on demand.

## 12. Migration rules

- File name: migrations/{YYYYMMDDHHMMSS}_{step}_{description}.sql with a matching _down.sql
- Idempotent: CREATE TABLE IF NOT EXISTS, ADD COLUMN IF NOT EXISTS, guarded DO blocks for enums
  and constraints
- Expand and contract for anything that touches a live table: add nullable, backfill in a job,
  enforce in a later migration
- Never drop a column in the same step that stops using it
- Every migration is applied by the CI gate before a merge is allowed
- Rollback path is documented in the handoff and exercised in staging at Step 16
